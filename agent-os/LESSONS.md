### L-016 — The spec's own conformance table describes the design's intent; the interactive artifact is what reviewers judge, and it silently disagrees
- **Date:** 2026-07-30
- **Category:** prd-trd
- **Scope:** general
- **Evidence:** **Three design-approval REJECTs in one day, on three different tasks, all first submissions, and all the same mechanism.** T-031 (`9f141e7`, 4 blocking + 5): `product`'s verdict states it outright — "**All four blocking findings are cases where the spec's prose says the right thing and the mockup does the opposite** — so §5's traceability table is accurate about the spec and wrong about the artifact." T-033 (`2777730`, 3 blocking + 3): spec claimed the map stays "interactive behind the sheet" while `.sheet-backdrop.show{pointer-events:auto}` + `inset:0` + `onclick="closeAll()"` swallowed every map tap; spec claimed `--primary` is "used nowhere else" — false in the source, three uses. T-032 (`6d0a4f7`, 2 blocking + 3): "§4 and §7 **both assert 4.5:1 contrast**… the artifact misses it on two label sets, in both themes" — recomputed at 3.22:1 and 3.61:1, with §4 stating the commitment as already met; and a `.day-flag` "next day" pill that renders in the artifact while §8 says the day-boundary question is "not resolved by this design pass" — "a developer building from the spec ships nothing; one building from the mockup ships an unspecced badge." Every one of these was found the same way, and both catchers say so unprompted: `product` — "**I read the artifact source, not the spec's description of it.** Fetched the full HTML/CSS/JS… Every number below is computed or quoted from that source, never from the relay or the designer's worklog"; `chief-of-staff` — "independently verified against the **raw mockup source**, not the relay summary." Note what did *not* prevent this: today's new designer.md item 8 (`ui-design-review` applied not cited, `dc34430`) was already live when T-032 was built, and T-032 still failed on a cited-and-asserted contrast number — because that review is run against the spec, where the claim lives, not against the artifact, where the pixels live.
- **Lesson:** When a deliverable is a prose document *plus* an executable artifact, the document's self-assessment sections — traceability, conformance, "requirement X is met" — are written from the author's intent, and intent is exactly what an artifact can diverge from without anyone noticing. The author checks the spec against the PRD and finds it complete; every gate downstream reads the spec's table and finds it complete; the artifact is never diffed against either. This is dangerous in proportion to how *good* the spec is: a spec that asserts a specific number ("4.5:1", "used nowhere else", "never a gradient") is more trusted and therefore less checked than one that hedges. The rule that follows is narrow and mechanical: every number and every absolute claim in the conformance/traceability sections must be **computed or quoted from the artifact's published source**, and every element the artifact renders must have a row in the spec — the two directions are different failures (an unmet claim vs. an undeclared component) and today produced both. The generalizable positive is the catch technique itself, which two independent reviewers converged on and named in the same words: read the artifact's source, not the document's description of it. That is the only control that finds this class, and it is cheap.
- **Action:** applied → `designer.md` (live `.claude/agents/` + `agents-mirror/` + `passenger-code/.claude/agents/`, all three synced): new deliverable item **9**, an artifact-conformance check run before submission — every number in items 5 and 7 recomputed or quoted from the published artifact source rather than from intent, and a both-directions sweep (no claim without a source line, no rendered element without a spec row), with any divergence fixed in *both* copies before submitting. Also folded the pre-existing `Paths` header drift on the `passenger-code` copy of this file back into sync in the same pass (see L-017). **Not** done here: a corresponding rule for `product`/`chief-of-staff` — they already do this correctly and unprompted at every one of the three gates, and codifying behaviour that is already universal adds a line without changing an outcome.

Both cannot be true; the unlabelled adjective silently answered the open question it sat beside. Caught only because `product`, dispatched for a concept read, diffed the stub's quote against each downstream summary word-for-word (PAS-11 comment `4bc2082e`, `66f36d7`) and re-labelled it **[ASSUMPTION]** plus new Open question #10, ahead of #8. `chief-of-staff` confirmed the gloss was its own on re-check (PAS-11 comment `b98384ad`). Structurally identical to this workspace's founding failure (`BOARD.md`: ten PRDs building forbidden features, "nobody read the strategy") except the premise wasn't forgotten — it was manufactured during the act of recording.
- **Lesson:** A verbatim quote and the recorder's paraphrase of it are two different evidentiary objects, and putting them inside one set of quotation marks destroys the distinction permanently. Downstream readers don't cite the quote, they cite the summary — so a single adjective added while transcribing becomes an unfalsifiable given premise, and the more load-bearing it is, the less likely anyone re-derives it.

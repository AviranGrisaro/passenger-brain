  - **Nav model:** heat/localness layer always-on directly on the map, 0 taps. Heat button opens a modal containing only the 12h time-slider + layer toggles. 3 main buttons (search, heat, 3rd TBD) built on native TabView/sheet-presentation primitives, not custom from scratch.   - **Search flow:** original ask was a literal 50/50 top/bottom map/list split. New decision: scenic + fast routing preview-only ARE in V1 — app draws the route as a polyline on the map for comparison; "Go" hands off to native Maps/Waze for actual turn-by-turn nav. No in-app turn-by-turn/voice/rerouting. Free in V1, no paywall.
  - **Map layers — SCOPE CHANGE from strategy.md, needs Aviran's real sign-off via redline.** Strategy currently locks "no Events overlay in V1; Phase 2 candidate." New decision: live events layer ships in V1 alongside heat + tag — **but it's launch-blocking**: V1 does not ship until data-engineer has a working live-events ingestion pipeline. Real timeline/dependency risk, needs a data-engineer scoping pass before being treated as committed.
  - **Accessibility/hierarchy fixes for `ux-flows.md` regardless of the above:** saved-place pins vs. search-result pins distinguished by shape/icon, not color alone. Time slider needs a visible numeral/label alongside any color coding, a discrete/announceable VoiceOver step size (not continuous-drag-only), and an explicit "now" tick mark. The 3(4)-button nav row + its modals should be classified **Sovereign** (dense/efficient, used dozens of times a session), not Transient.
  - **Still open, NOT decided — do not pick for Aviran:** the 3rd nav button. Options on the table: (a) drop it, ship 2 buttons only; (b) scope it to device-local settings only (no name/login/persisted profile — permission status, notifications, units); (c) fully reopen V1 scope for accounts + the existing "Passport" Phase-2 concept.
